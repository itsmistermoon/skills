Start with `Handing over session...` in the user's language. Use that language for confirmations. The Git root containing CWD is the base repo, including in a worktree.

## Steps

1. **Resolve context.** Find the base repo; ask if CWD is not inside a Git repository. Resolve the scope from `scope:<path>,<path>`, else the `Scope:` line in the base repo's `## Mission control`, else the base repo alone. Each entry is a repo path, absolute or relative to the base root; resolve it to its Git root and deduplicate. If an entry is invalid, stop and ask. Add the base repo to the resolved scope: the handover always writes its state there. The scope is the complete list of repos whose state this agent owns. Identify the invoking agent and model when known, otherwise use `Unknown agent`. **Tracker:** read [TASK-TRACKER.md](../mcc-setup/references/TASK-TRACKER.md) before resolving or changing pending work; execute its List, Add, and Close contracts for each destination. Parse `scope:` and `next: <focus>` separately from any vault/project arguments. **Done when:** the base, scope, language, agent, next focus, and task tracker are known.

2. **Prepare state.** **Snapshot format:** read [HANDOVER-FORMAT.md](references/HANDOVER-FORMAT.md) and the existing `.mcc/HANDOVER.md`, if present. Validate existing state against that format before editing; if it is unreadable or malformed, leave it intact and report the problem. Create `.mcc/` when needed and add it to `.gitignore`. Remember whether `.mcc/` existed before this run. Rotate History so HANDOVER keeps only its two most recent entries (three after step 4 appends this session's): append each older entry verbatim, oldest-first, to `.mcc/HISTORY.md`, then remove the successfully archived entries from HANDOVER. Create HISTORY with a `# {repo-name}: history` header if needed. Preserve the order of all remaining entries. **Done when:** HANDOVER holds at most two History entries, or a write failure has been reported with the original state preserved.

3. **Capture operational lessons.** **Lessons:** read [PLAYBOOK-FORMAT.md](references/PLAYBOOK-FORMAT.md) before classifying and recording candidates. Review this session for reusable workarounds, user preferences, conventions, and recurring failure patterns. For each candidate, identify the repo named by its evidence (path, command, PR, or issue); resolve ambiguous evidence before writing. In each matching scoped repo, read its `.mcc/PLAYBOOK.md` if present and record the lesson with its evidence, adding evidence to a matching entry. Create `.mcc/` and add it to that repo's `.gitignore` when needed. Point to authoritative documents when they already contain the lesson. Leave retrospective pruning to `/mcc-debrief`. For every session item about an out-of-scope repo, use the tracker's Add operation with that repo as destination, including its evidence and action needed. Keep the snapshot limited to scoped state and tracker entries. If routing fails or ownership cannot be resolved, report the item as uncaptured. **Done when:** every candidate is recorded in its evidence repo, already documented, rejected as transient, routed to its repo's tracker, or reported as uncaptured.

4. **Write the snapshot.** Update Current state and append a History entry using the format from step 2. Reconcile duplicates and resolved or superseded items in Current state; preserve previous History entries. Apply the Active decisions limit from HANDOVER-FORMAT. Carry `### Decision queue` forward as it stands: struck items with their result, open ones in order. Tailor pending work to `next:` when supplied.

   - **Pending work:** List the tracker's open tasks for the scope, then Add each new one in its repo through the tracker's Add contract, and Close each one this session finished or dropped. Route out-of-scope items as in step 3.
   - **Local vault health:** if `{repo}/meta/vault-report.json` exists, read `health.dead_links`, `health.raw_without_source_page`, `health.missing_confidence`, `health.orphan_pages`, `health.missing_raw`, `health.unindexed_pages`, and `health.duplicate_sources`. Keep one dated pending task with the finding count and report path while the report is nonempty, and Close it when the report is empty. Mention unresolved findings explicitly in the confirmation.
   - **Maintenance nudge:** for each scoped PLAYBOOK whose oldest Working-context date is over 30 days old, add a pending task in that repo to run `/mcc-debrief` for overdue pruning. On the first handover only, if AGENTS.md lacks `<!-- mcc:session-start -->` or the `## Mission control` section, suggest `/mcc-setup`. This skill does not edit AGENTS.md.

   **Done when:** every durable decision, event, lesson, and task from the session is classified by repo; every scoped item is saved in its designated destination, already documented, or reported as uncaptured; every external item is routed through Add or reported as uncaptured; the snapshot contains scoped state and tracker entries only, history is preserved, and sensitive content is omitted.

5. **Optional project update.** Only if the user supplied a vault argument, requested a project-page update, or this session consulted a vault for the active project, read [PROJECT-UPDATE.md](references/PROJECT-UPDATE.md) and follow its steps. Complete the local handover first. Resolve the Git root of every destination, including the project page and `wiki/log.md`, before writing either. Write only when every destination is inside scope; route each out-of-scope destination through the tracker as in step 3. Report any destination whose ownership cannot be resolved as uncaptured. A missing vault or unavailable project page leaves the local snapshot complete. **Done when:** every destination is updated under authorization, routed through the tracker, or reported as skipped or uncaptured with its reason.

## Confirmation

Start with the absolute path of the base `.mcc/HANDOVER.md` written. Give a table with one row per repo touched in the session: repo, PLAYBOOK changes, tracker additions or changes (IDs or URLs when available), and whether it is in scope. Include out-of-scope items and any uncaptured items with their reasons. Report a one-line History summary and any project page updated. State either `Safe to end: everything durable from this session is captured` or `Not fully captured: {what is missing and why}`. Give a resume pointer starting with `.mcc/HANDOVER.md` Current state, adding PLAYBOOK only when relevant. Older history is read only when needed.
